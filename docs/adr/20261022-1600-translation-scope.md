# 翻訳の範囲と原文の下ごしらえ

- 日付: 2026-10-22
- 状態: 採用

## 背景

TanStack Table v9 の公式ドキュメント（上流 `TanStack/table` の `docs/`）は、11のフレームワーク向けページと、TypeDoc が自動生成した API リファレンス約1,500ファイルからなる。React 利用者が日本語で学べるようにしたいが、全量を訳すのは作業量に見合わない。

## 決定

1. **React 向けに絞る。** フレームワーク共通のページ（概要・インストール・コアガイド）と `docs/framework/react/` だけを収録する
2. **API リファレンスは React 分だけ訳す。** `docs/framework/react/reference/`（64ファイル）は訳す。コア側の `docs/reference/`（約700ファイル）は英語のまま収録する
3. **フレームワーク切り替えブロックは React の節だけを残す。** 翻訳前に機械的に処理する
4. **見出しに英語のアンカー `{#slug}` を固定する。** 見出しを訳してもページ内リンクが切れないようにする
5. **サンプル集は収録しない。** サイドバーから公式サイトのサンプルへ外部リンクする

## 理由

- コア API リファレンスの大半は型シグネチャで、訳して得られる価値に比べて量が多い。上流の更新頻度も高く、訳文の追従が難しい
- React 向けリファレンスは `useTable` や `createTableHook` など、React 利用者が最初に引くページなので訳す価値が高い
- アンカーを固定しておけば、上流の英語の見出しを前提に書かれたリンク（`#rendering-is-a-separate-decision` など）がそのまま使える

## 採らなかった案

- **コア API リファレンスも訳す:** 作業量がガイドの約2倍になり、上流の更新にも追従しにくい
- **リファレンスを収録しない:** ガイドから `../reference/...` へのリンクが多く、リンク切れが増える
- **見出しのアンカーを日本語にする:** 原文由来のページ内リンクをすべて書き換える必要がある

## 影響

- サイト内検索ではコア API リファレンスが英語でヒットする
- 上流を更新するときは、取り込み直してから同じ下ごしらえ（React 節の抽出・リンク書き換え・アンカー付与）を再実行する
