# コア API リファレンスも日本語に訳す

- 日付: 2026-10-25
- 状態: 採用（[20261022-1600-translation-scope](20261022-1600-translation-scope.md) の決定2のうち、コア API リファレンスを英語のまま収録する部分を置き換える）

## 背景

10/22 の決定では、`docs/reference/`（693ファイル）を英語のまま収録した。その結果、ガイドから API ページへ移ると急に英語になり、サイト内検索でも英語のページがヒットしていた。利用者から、API のページもすべて訳してほしいという依頼があった。

## 決定

1. **`docs/reference/` の全693ファイルを訳す。** 訳す範囲は React API リファレンスと同じで、説明文、TypeDoc の定型の見出し、`Defined in:` の3つ
2. **訳は段落単位の対訳表から機械的に当てはめる。** TypeDoc の出力は同じ説明文が複数のページに出る（継承されたメンバーなど）。重複を除くと説明文は1,400段落なので、段落ごとに1回だけ訳し、全ページへ同じ訳を当てる
3. **見出しのアンカーは英語の見出しから作る。** 既存の `scripts/anchors.py` と同じ規則で、訳す前の見出しに `{#slug}` を付けてから訳す
4. **新しい定型句の訳語を決める。** `Inherited from` は「継承元のメンバー」、`Overrides` は「上書き元」とする。`Extends` の訳「継承元」と同じページに並ぶため、別の語にした

## 理由

- 段落単位の対訳表にすると、同じ英文には必ず同じ訳が付き、ページ間で訳が揺れない
- コードブロック、リンク、frontmatter は当てはめの処理で触らないので、壊れていないことを機械的に確かめられる

## 採らなかった案

- **ページごとに訳す:** 同じ説明文を何度も訳すことになり、作業量が増えて訳も揺れる
- **よく引くページだけ訳す:** どこまで訳したかの線引きが利用者から見えず、10/22 の決定と同じ問題が残る

## 影響

- 上流を取り込み直したときは、変わった段落だけを対訳表に足せば追従できる。ただし、対訳表と当てはめのスクリプトは今回リポジトリに入れていないので、次回は作り直す必要がある
- サイドバーの「（英語）」の表記を外した
